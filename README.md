Obscura Launcher --- Linux Build Guide
Версия: 1.1.0
Платформа: Linux x86_64 (AMD64)
Технологии: Electron, Node.js, electron-builder

Это руководство описывает получение исходного кода, установку зависимостей, сборку и запуск Obscura Launcher в Linux. Команды и доступность пакетов могут отличаться в зависимости от версии дистрибутива.

1. О проекте
Obscura Launcher --- лаунчер Minecraft: Java Edition, созданный на Electron.

Возможности и доступность отдельных функций зависят от версии проекта. Лаунчер может включать управление игровыми версиями, загрузчиками модификаций, профилями, авторизацией и настройками запуска.

2. Системные требования
Компонент Требование

Архитектура x86_64 / AMD64 Node.js 22 или новее npm Поставляется вместе с Node.js Оперативная память Рекомендуется от 4 ГБ для разработки и сборки Свободное место Рекомендуется не менее 3 ГБ Интернет Нужен для загрузки зависимостей и игровых файлов

Текущие команды сборки рассчитаны на Linux x86_64. Для ARM64 потребуется отдельная настройка конфигурации сборки и проверка зависимостей.

3. Подготовка системы
Обновите пакеты своей системы.

Ubuntu / Debian / Linux Mint
sudo apt update
sudo apt upgrade -y
Fedora
sudo dnf upgrade --refresh -y
Arch Linux / Manjaro
sudo pacman -Syu
openSUSE
sudo zypper refresh
sudo zypper update
4. Установка Node.js
Для сборки рекомендуется Node.js 22 или новее. Удобный способ установить и переключать версии Node.js --- NVM.

Установка NVM:

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
Перезапустите терминал. Если команда nvm не найдена, для Bash выполните:

source ~/.bashrc
Для Zsh:

source ~/.zshrc
Установите Node.js 22:

nvm install 22
nvm use 22
nvm alias default 22
Проверьте версии:

node -v
npm -v
5. Установка системных зависимостей
Electron и инструменты упаковки могут использовать системные библиотеки. Установите зависимости для своего дистрибутива.

Ubuntu / Debian / Linux Mint
sudo apt install -y \
  build-essential curl ca-certificates git unzip \
  libgtk-3-0 libnotify4 libnss3 libxss1 libxtst6 \
  libatspi2.0-0 libsecret-1-0 fakeroot dpkg
Для запуска AppImage может потребоваться FUSE 2:

sudo apt install libfuse2
В некоторых новых выпусках Ubuntu пакет называется libfuse2t64:

sudo apt install libfuse2t64
Fedora
sudo dnf install -y \
  curl git unzip gcc gcc-c++ make gtk3 libnotify nss \
  libXScrnSaver libXtst at-spi2-atk libsecret fuse-libs
Arch Linux / Manjaro
sudo pacman -S --needed \
  curl git unzip base-devel gtk3 libnotify nss libxss \
  libxtst at-spi2-core libsecret fuse2
openSUSE
sudo zypper install \
  curl git unzip gcc gcc-c++ make gtk3 libnotify \
  mozilla-nss libXss1 libXtst6 libsecret-1-0 fuse
Названия пакетов могут меняться между версиями дистрибутивов. Если пакет не найден, найдите его актуальное название в документации или репозитории своей системы.

Для создания DEB-пакета необходимы инструменты упаковки Debian, включая dpkg и fakeroot. Сборка AppImage или TAR.GZ может быть доступна и без них.

6. Получение исходного кода
Скачайте ZIP-архив исходного кода Obscura Launcher из официального источника проекта и распакуйте его.

Например:

unzip Obscura-Launcher-1_1_0-Linux.zip
cd Obscura-Launcher-1_1_0-Linux
Если вы используете Git:

git clone <URL-РЕПОЗИТОРИЯ>
cd <ПАПКА-ПРОЕКТА>
Замените адрес и имя папки на фактические значения своего репозитория.

Проверьте, что вы находитесь в корневой папке проекта:

ls -la
В ней должен находиться package.json. Также проверьте наличие скрипта build-linux.sh, если планируете использовать автоматизированную сборку.

7. Установка зависимостей проекта
В корневой папке проекта выполните:

npm install
Дождитесь окончания установки. Для этой операции требуется подключение к интернету.

Если в репозитории есть package-lock.json и вы хотите установить зафиксированные версии зависимостей, можно использовать:

npm ci
npm ci удаляет существующую папку node_modules и устанавливает версии строго по lock-файлу.

8. Запуск из исходников
Чтобы запустить приложение в режиме разработки, выполните:

npm start
Если команда не определена в package.json, проверьте доступные скрипты:

npm run
9. Проверка проекта
Перед сборкой рекомендуется запустить тесты:

npm test
Если в package.json определён скрипт диагностики, его можно запустить так:

npm run doctor
Не все версии проекта обязательно содержат все перечисленные скрипты. Команда npm run показывает фактически доступные команды.

Если тесты завершаются ошибкой, сначала устраните её или изучите вывод тестов. Не публикуйте сборку, не проверив критические ошибки.

10. Сборка приложения
Вариант A --- штатный скрипт проекта
Если в архиве присутствует build-linux.sh, это наиболее простой способ сборки:

chmod +x build-linux.sh
./build-linux.sh
Скрипт может устанавливать зависимости, запускать проверки и вызывать сборщик. Следите за выводом терминала: конкретные действия определяются содержимым скрипта.

Вариант B --- команда npm
Если в package.json определён скрипт dist:linux, выполните:

npm run dist:linux
После успешной сборки проверьте папку:

ls -lah dist/
Ожидаемые форматы, если они включены в конфигурацию проекта:

AppImage
DEB
TAR.GZ
Имена файлов и доступные форматы зависят от настроек electron-builder и версии проекта.

11. Сборка отдельных форматов
Если соответствующие команды настроены в package.json, можно собрать только AppImage:

npm run dist:linux:appimage
Для DEB можно использовать electron-builder напрямую:

npx electron-builder --linux deb --x64
Для TAR.GZ:

npx electron-builder --linux tar.gz --x64
Если команда dist:linux:appimage отсутствует, посмотрите список доступных скриптов:

npm run
Сборка DEB выполняется на Linux с установленными инструментами упаковки Debian. Для AppImage могут потребоваться дополнительные системные компоненты, включая FUSE для запуска готового файла.

12. Установка готового приложения
Готовые файлы обычно располагаются в dist/.

12.1. AppImage
AppImage --- переносимый формат приложения. Обычно его не требуется устанавливать через системный пакетный менеджер.

Перейдите в папку сборки:

cd dist
Разрешите запуск:

chmod +x ./*.AppImage
Запустите файл:

./ИМЯ-ФАЙЛА.AppImage
Можно хранить AppImage, например, в ~/Applications:

mkdir -p ~/Applications
cp ./*.AppImage ~/Applications/
Затем запускайте его из этой папки.

Ошибка FUSE
Если AppImage сообщает об отсутствии FUSE, установите пакет FUSE 2 для своего дистрибутива. В Ubuntu/Debian это обычно libfuse2, а в некоторых новых версиях Ubuntu --- libfuse2t64.

12.2. DEB
DEB предназначен для Debian, Ubuntu, Linux Mint и совместимых систем.

Установите пакет из папки dist:

sudo apt install ./ИМЯ-ФАЙЛА.deb
Если установка через apt недоступна, можно использовать:

sudo dpkg -i ИМЯ-ФАЙЛА.deb
sudo apt --fix-broken install
Удаление выполняется по имени установленного пакета. Посмотреть сведения о DEB-файле можно командой:

dpkg-deb -I ИМЯ-ФАЙЛА.deb
12.3. TAR.GZ
Распакуйте архив в отдельную папку:

mkdir -p ~/Applications/Obscura
tar -xzf ИМЯ-ФАЙЛА.tar.gz -C ~/Applications/Obscura
Посмотрите содержимое:

find ~/Applications/Obscura -maxdepth 3 -type f
Найдите исполняемый файл приложения и запустите его. Если у файла нет права на выполнение:

chmod +x ПУТЬ-К-ИСПОЛНЯЕМОМУ-ФАЙЛУ
Структура архива зависит от конфигурации electron-builder.

13. Решение проблем
node: command not found или npm: command not found
Проверьте установку Node.js и загрузите настройки NVM:

source ~/.bashrc
nvm use 22
node -v
npm -v
Если NVM не установлен, выполните инструкции из раздела 4.

Permission denied
Для скрипта сборки:

chmod +x build-linux.sh
Для AppImage:

chmod +x ИМЯ-ФАЙЛА.AppImage
Cannot find module
Переустановите зависимости:

rm -rf node_modules
npm install
Если присутствует package-lock.json, можно выполнить npm ci.

Ошибка при установке npm-зависимостей
Проверьте интернет-соединение и состояние npm-кэша:

npm cache verify
npm install
AppImage не запускается
Проверьте права на выполнение и наличие FUSE. Для диагностики запустите приложение из терминала и сохраните полный текст ошибки.

Ошибка Failed to load shared library
Установите отсутствующую библиотеку из репозитория своего дистрибутива. Название пакета может отличаться от имени файла библиотеки.

Ошибка Sandbox / AppArmor
В некоторых конфигурациях Linux запуск Electron может блокироваться настройками песочницы или AppArmor. Сначала изучите сообщение об ошибке и проверьте системные настройки.

--no-sandbox отключает песочницу Chromium и снижает безопасность приложения. Не используйте его как постоянное решение и не запускайте приложение с этим параметром, если не доверяете исходному коду и сборке.

Сборка завершается ошибкой
Соберите диагностическую информацию:

node -v
npm -v
npm run
npm test
Затем повторите сборку и сохраните полный вывод терминала. При обращении за помощью приложите текст ошибки, версию дистрибутива и архитектуру процессора.

14. Данные пользователя и Minecraft
Путь хранения пользовательских данных зависит от настроек приложения и используемых API Electron. Для приложений Electron стандартная директория конфигурации Linux обычно находится внутри ~/.config/.

Не удаляйте пользовательскую папку приложения, если хотите сохранить настройки, профили, игровые файлы или данные авторизации.

Перед переустановкой или удалением данных сделайте резервную копию.

Java и Minecraft
Для запуска Minecraft: Java Edition требуется подходящая версия Java. Требования зависят от версии Minecraft и используемого загрузчика модификаций.

Например, в Ubuntu можно установить Java 21:

sudo apt install openjdk-21-jre
Проверить установленную Java:

java -version
Если лаунчер поддерживает автоматическую установку Java Runtime, следуйте подсказкам самого приложения.

Для запуска Minecraft также нужны совместимые графические драйверы и поддержка необходимых версий OpenGL.

Авторизация Microsoft
Для игры на официальных онлайн-серверах требуется действующая лицензия Minecraft: Java Edition, привязанная к Microsoft-аккаунту.

Для работы авторизации могут потребоваться корректные настройки OAuth и доступ к системному хранилищу секретов. На Linux это обычно GNOME Keyring или KWallet. Конкретные требования зависят от реализации авторизации в версии проекта.

15. Ограничения
Инструкция рассчитана на Linux x86_64.
Сборка ARM64 требует отдельной настройки.
Для AppImage может понадобиться FUSE 2.
Для DEB нужны инструменты упаковки Debian.
Системные зависимости различаются между дистрибутивами и их версиями.
Работа на всех Linux-системах и конфигурациях оборудования не гарантируется.
Наличие конкретного npm-скрипта проверяйте через npm run.
Быстрая сборка
Если Node.js 22+, системные зависимости и исходный код уже подготовлены, попробуйте:

npm install
npm test
npm run dist:linux
Или используйте скрипт проекта, если он присутствует:

chmod +x build-linux.sh
./build-linux.sh
Готовые файлы ищите в папке dist/.
